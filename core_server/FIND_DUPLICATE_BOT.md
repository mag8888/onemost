# Поиск дублирующего экземпляра бота

## Проблема

Ошибка Conflict означает, что где-то еще запущен другой экземпляр бота с тем же токеном.

## Где искать

### 1. Проверьте все сервисы в Railway проекте "onemost"

1. Откройте проект **"onemost"** в Railway
2. Проверьте **ВСЕ** сервисы в проекте:
   - "onemost" (основной сервер)
   - "onemost-bot" (бот)
   - Любые другие сервисы

3. Для каждого сервиса проверьте:
   - **Start Command** - не запускает ли он бота?
   - **Status** - не запущен ли он?
   - **Variables** - есть ли `TELEGRAM_BOT_TOKEN`?

### 2. Проверьте другие Railway проекты

1. Откройте **все** ваши Railway проекты
2. Проверьте каждый проект на наличие:
   - Сервисов с `TELEGRAM_BOT_TOKEN`
   - Сервисов, запускающих бота

### 3. Проверьте старые деплои

1. В сервисе **"onemost-bot"** откройте вкладку **"Deployments"**
2. Проверьте, нет ли старых активных деплоев
3. Остановите все старые деплои

### 4. Проверьте количество реплик

1. В сервисе **"onemost-bot"** откройте **"Settings"** → **"Regions"**
2. Убедитесь, что установлено **"1 Instance"**
3. Если больше - уменьшите до 1

## Решение

### Шаг 1: Остановить ВСЕ экземпляры бота

1. Остановите сервис **"onemost-bot"**
2. Проверьте и остановите все другие сервисы, которые могут запускать бота
3. Подождите **2-3 минуты**

### Шаг 2: Проверить все проекты

1. Проверьте все Railway проекты
2. Убедитесь, что нигде больше не запущен бот с тем же токеном

### Шаг 3: Запустить только один экземпляр

1. Запустите только сервис **"onemost-bot"**
2. Убедитесь, что других экземпляров нет
3. Проверьте логи - конфликт должен исчезнуть

## Альтернативное решение: Использовать другой токен

Если не можете найти дублирующий экземпляр:

1. Создайте нового бота через @BotFather
2. Получите новый токен
3. Обновите `TELEGRAM_BOT_TOKEN` в Railway
4. Перезапустите сервис

## Проверка

После исправления в логах должно быть:
```
Bot initialized successfully
Application started
```

Без ошибок Conflict!
