# Исправление ошибки Pre-deploy command

## Проблема

Ошибка: "Pre-deploy command failed" при выполнении `python manage.py migrate`

## Причины

1. **База данных недоступна** - `DATABASE_PUBLIC_URL` не настроен или неправильный
2. **Миграции требуют интерактивного подтверждения** - нужно добавить `--noinput`
3. **Проблемы с подключением** - база данных еще не готова

## Решение

### Вариант 1: Убрать Pre-deploy, выполнять миграции в Start Command (реализовано)

Миграции теперь выполняются в `startCommand` с флагом `--noinput`:

```json
"startCommand": "python manage.py migrate --noinput && python manage.py runserver 0.0.0.0:${PORT:-8000}"
```

**Преимущества:**
- Миграции выполняются каждый раз при запуске
- Если миграции уже применены, команда просто пропустит их
- Более устойчиво к ошибкам

### Вариант 2: Проверить переменные окружения

Убедитесь, что в Railway настроены:

```env
DATABASE_PUBLIC_URL=<скопируйте из центрального сервера>
```

**Как получить:**
1. Откройте центральный сервер "onemost" в Railway
2. Перейдите в **"Variables"**
3. Найдите `DATABASE_PUBLIC_URL`
4. Скопируйте значение
5. Вставьте в MLM сервер $100

### Вариант 3: Использовать DATABASE_URL вместо DATABASE_PUBLIC_URL

Если серверы в одном проекте Railway, можно использовать `DATABASE_URL` через Reference:

1. В Railway откройте MLM сервер $100
2. Перейдите в **"Variables"**
3. Нажмите **"+ New Variable"**
4. Выберите **"Reference"**
5. Выберите сервис с PostgreSQL
6. Выберите переменную `DATABASE_URL`

## Проверка

После исправления:
1. ✅ Миграции должны выполниться успешно
2. ✅ Сервер должен запуститься
3. ✅ В логах не должно быть ошибок подключения к базе данных

## Логирование

Добавлено логирование в `settings.py` для отладки:
- Показывает, найден ли `DATABASE_PUBLIC_URL`
- Показывает хост базы данных при успешном подключении
- Показывает ошибки при проблемах с подключением
